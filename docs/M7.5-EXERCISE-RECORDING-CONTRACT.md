> This is a Stage 1 correction, not a Stage 2 or deployment handoff.

## 1. Authorized outcome

Each Exercise Definition owns a recording type and exactly one primary progress metric. A second
stored metric means the comparison is unlocked and is supporting context, never a second primary
metric. Recording type determines the set-entry fields; the ordered metric selection determines
the primary line, optional secondary bars, performance summaries, and history columns. RPE remains
the single intensity field.

The owned surfaces are Exercise Library, Session Training, the shared growth-trajectory dialog,
and only the Training settings panel. This does not start the broader Student or Settings route
review. Shared Student performance and public Training Result consumers must remain compatible.
The archived Demo and its storage format remain unchanged.

## 2. Confirmed product decisions

Product Owner confirmed both choices in this session:

1. **Timed counting:** duration + rounds (for example, 60 seconds and 5 rounds). The sole
   primary metric is rounds. Repetitions-in-time is not an additional recording type.
2. **Distance + duration:** shortest duration at the same normalized distance; pace is minutes
   per kilometre, lower is better. The chart offers a distance selector for time comparisons.
   Pace can compare different distances; zero duration/distance produces no pace achievement.

## 3. Recording and progress vocabulary

| Recording type | Entered dimensions  | Allowed primary progress metrics |
| -------------- | ------------------- | -------------------------------- |
| 重量 × 次數    | weight, repetitions | weight, repetitions              |
| 次數           | repetitions         | repetitions                      |
| 重量 × 時間    | weight, duration    | duration, weight                 |
| 時間           | duration            | duration                         |
| 距離 × 時間    | distance, duration  | duration, pace                   |
| 重量 × 距離    | weight, distance    | weight, distance                 |
| 距離           | distance            | distance                         |
| 時間 × 回合數  | duration, rounds    | rounds                           |

For a type with one allowed metric, select and lock it automatically. For two, the first selected
item is the unique primary metric and the second item is the secondary metric. Both are initially
present (unlocked). Clicking the current primary toggles locked/unlocked; switching to the other
metric makes that item primary and leaves comparison unlocked. The selection must be nonempty,
ordered, unique, and contained in that type's allowed metrics. Changing recording type resets the
proposed selection to its allowed metrics in the editor before submission. RPE is optional and
retains the existing 1–10 / 0.5 validation. Result retains completed, incomplete, and the existing
unrecorded null state.

The new set editor has one or two measurement inputs, RPE, result, and remove-set control.
Remove the separate actual-repetitions input from new-format sets. A number alone never marks a
set complete; the Coach chooses its result. A completed set contributes only when the values
required by its recording type are present. Blank remains null and is never converted to zero.

## 4. Units and numeric interpretation

Training settings hold only the Coach's weight (`kg` / `lb`) and distance convention (metric
`km` / imperial `mi`). Repetitions are always `次`; rounds are always `回合`; time has no global
preference. A new record uses the chosen weight convention without offering an in-record weight
switch. Distance can quickly switch only within its convention (`m` / `km` or `ft` / `mi`), and
time can quickly switch `sec` / `min`; those switches convert the entered value and are not
dropdown menus. The initial distance scale follows the occurrence context (distance + duration
starts at the long scale; other distance records at the short scale), rather than treating metres
versus kilometres as a Workspace preference. Pace is derived from distance and elapsed time, not
an independently editable input; its display convention is minutes per kilometre.

Persist entered values together with their original units. A preference change affects new input
defaults and converted performance presentation; it never relabels an old number without
conversion. An existing set retains its original units when edited. Compare normalized values
before display rounding. One minute equals 60 seconds; one kilometre equals 1,000 metres; one
mile equals 1,609.344 metres; one foot equals 0.3048 metres. A zero distance or duration cannot
produce a finite pace and does not enter a pace series. Negative, nonfinite, excessive-precision,
and fractional count inputs are rejected. Weight is 0–10,000; duration/distance 0–1,000,000 in
entered units (up to 3 decimal places); counts are integers 0–10,000.

## 5. Data and operation boundaries

- Training owns recording types, measurements, primary metrics, and preferences. All writes
  remain behind verified Coach identity and Workspace-scoped API operations.
- Extend Exercise Definition with recording type and selected primary metrics. Preserve stable
  IDs, catalog keys, favorites, deletion state, and unrelated edited definition text.
- Snapshot recording type on each newly inserted Training Exercise occurrence. Existing
  occurrence types never change when the library changes. Never trust client-supplied snapshot
  text or types in place of a version-checked definition.
- Store new set dimensions separately from legacy weight/repetition fields. Use explicit format
  identification so old queue requests cannot erase new measurements by omission.
- Keep definition, preference, and record version checks and operation receipts. A response-lost
  retry replays the exact accepted operation; changing payload requires a new operation ID.
- Chart visibility writes only the definition's selected primary metrics using its version.
  It must not submit a stale copy of name/equipment/favorites or rewrite occurrence snapshots.
  This is a Workspace-owned exercise preference and therefore also applies when viewing another
  Student's trajectory for that Exercise Definition.
- Return all compatible available series plus selected metrics, units, and comparison direction
  from the server. Hiding a series does not discard its records or stop collecting its dimension.
  Reopening it requires no reinterpretation of history.
- Derive personal/previous/current bests on the server, grouped by definition identity and
  compatible recording dimensions. Do not join renamed definitions by their display names.
- Update Today plan completeness to use the occurrence's required dimensions. Do not leave
  a duration-only exercise permanently incomplete because it has no planned repetitions.

## 6. Existing records, catalog, drafts, and import

Existing records preserve their original weight, planned repetitions, actual repetitions, RPE,
result, and unit. Do not turn a historic plank repetition value into seconds, nor a carry's
repetition value into metres. Retain original actual-repetition facts even after removing that
field from the new editor. A legacy occurrence needs an explicit compatible display/edit path;
its legacy fields cannot be silently overwritten during an unrelated save.

Classify every current default definition by stable catalog key. Produce a full mapping with
target type and metrics before migration. The catalog contains 100 definitions; notable
corrections include plank/side plank → duration, kettlebell farmer walk → weight + distance,
and elastic-band repetition exercises → repetitions. Battle rope and burpee use duration + rounds as confirmed in §2. Repetition-based loaded movements retain weight + repetitions. Assisted pull-up
uses repetitions as its progress metric; assistance weight must not be mislabeled as increasing
lifting strength. Deleted defaults stay deleted; migration does not create duplicates.

New catalog bootstrap and existing Workspace backfill must use the same manifest. Preserve
Coach-owned edits and handle a changed name/equipment explicitly rather than classifying from
a possibly unrelated old catalog key alone. Record changed/skipped counts in migration evidence.

Version and normalize recoverable drafts/queued operations explicitly. Preserve canonical
Coach/Session ownership, editor handoff, coalesced autosave, lost-response replay, and automatic
cleanup. Test old queued input arriving after migration and a new record being edited in an old
tab. Demo import/preview/rollback must continue to recognize legacy values and snapshot semantics;
no modification to `form-coach-mvp-v1` is authorized.

## 7. Presentation and interaction contract

- Preserve FORM typography, card scale, colors, dim-only dialogs, and custom `FormSelect`.
- Definition editor: `紀錄類型`, then `主要進步指標`. Two-metric types use the shared compact
  selector; the active metric carries a lock/unlock icon instead of explanatory state copy. A
  one-metric type renders as a static primary-metric fact, never a disabled-looking control.
  Library cards expose the selected type and meaningful metric labels.
- Session: type-specific field labels and visible units, without `實際次數` for new-format
  sets. Adding a set copies compatible numeric defaults only, never RPE or result.
- Trajectory: retain desktop 10/20 and mobile 5/10 record ranges. Display the unique primary metric
  as the labeled line in the upper chart region. When unlocked, display the secondary metric as
  borderless dark low-opacity bars constrained to the bottom 20–30% of the plot. Keep a deliberate
  gap between both regions, remove the right-side scale entirely, and show only the primary scale
  on the left. Missing values are gaps, not zero. Keep controls visible in an empty series.
- The primary line retains point labels. Secondary bars carry a small value label on every bar;
  their quiet contrast keeps the primary line dominant while their full values remain available
  through accessible titles.
- Each metric control changes the definition's ordered persistent selection using the same
  lock/unlock behavior as the Definition editor. The visible icon, selected surface, line, and
  quiet bars carry this hierarchy; do not add tutorial copy to explain it.
- The trajectory overview shows only the primary metric's `最新紀錄` and `區間最佳紀錄`; the
  history list has one row per Course Session and only its primary value. Bests for two metrics can
  come from different completed sets, so do not present them as one achieved combination.
- Pending chart-setting writes retain the chart and show a small saving state; failed writes
  retain/recover the user's intent with a visible retry action, never claim server acceptance.
  Concurrent changes reconcile against the returned version without overwriting other fields.
- Keep initial loading, empty, cached refresh, error/retry, mutating, and conflict boundaries
  local to their panels. A failed preference update cannot blank the Session workspace.
- Shared public Training Result and downloaded image show the same recording dimensions and
  units through a purpose-specific allowlist. Private notes remain excluded unless already
  explicitly opted into that capability link.
