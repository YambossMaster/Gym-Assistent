# M3.5-A5 Contract — Supported-data product convergence and delivery

> Frozen 2026-09-13. Product Owner authorized the final M3.5 package after A1–A4 delivery. A5
> makes no schema, API, Module, authorization, cache-policy, or scheduling change; it converges
> only the supported M0–M3 product surface and completes the milestone delivery evidence.

## 1. Coach job and surface boundary

A signed-in Coach needs a calm, dependable place to sign in, orient to the current Workspace,
inspect the M3-supported Today signals, manage Students and Lesson Purchases, and maintain account
settings. Each available action must truthfully describe what it can do, remain usable by keyboard
and touch, and preserve usable cached data while a background refresh occurs.

| Surface                      | Frozen A5 responsibility                                                                                                                                    |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth and recovery            | Converge the existing email/password, Google, six-digit verification, reset, and recovery views without changing Auth operations or validation.             |
| App Shell                    | Give supported Coach routes one clear desktop/mobile navigation and identity treatment; preserve cache-safe route changes and scroll reset.                 |
| `/today`                     | Present the existing local-date, active-Student, local-month income, and entitlement-attention projection without schedule claims.                          |
| `/students`, `/students/:id` | Converge the existing roster, Student context, entitlement, and versioned Purchase workflows without inventing Calendar, Training, or payment behaviour.    |
| `/settings`                  | Converge independent profile/lifecycle states and the existing security/destructive operations without adding workflow, notification, or Calendar settings. |

`/calendar`, `/sessions/:id`, and `/exercises` remain outside M3 authority. They stay visibly
unavailable with a concise, non-actionable explanation and no fake data, disabled-looking primary
action, roadmap/milestone wording, or promised date. `/t/:token` and `/r/:token` remain M6 work
and receive no A5 route or Auth-gate change.

## 2. Demo comparison and deliberate deviations

The archived Demo remains the reference for FORM Coach Desk's quiet, high-contrast workbench,
information hierarchy, active/archive roster intent, lesson-account attention, calm forms, and
responsive PWA composition. A5 preserves that language with the existing formal visual primitives;
it does not copy Demo seed values, local-storage behaviour, schedule views, fixed rhythm,
availability, reminders, LINE controls, training history, exercise controls, or public-link flows.

The Demo's Today agenda, Calendar, session workspace, and Exercise Library depend on M4/M5 data.
Their absence is honest product state, not an empty schedule, a broken navigation, or an
implementation-status message. A5 removes implementation-facing rendered language, including
references to roadmaps, contracts, cache mechanics, schemas, milestones, agents, and "content will
be ready" promises. Existing factual error, refreshing, private-note, and account-deletion copy
remains permitted.

## 3. Frozen product and copy decisions

- The visual direction is a restrained FORM workbench: ink/dark surfaces, warm paper-like panels,
  lime only for focused primary intent, and red only for destructive intent. Existing CSS tokens and
  lucide icons remain the shared system; no new font, image asset, external dependency, or design
  system is introduced.
- Use a single descriptive `h1` per route. Keep the familiar compact uppercase eyebrow as a visual
  label only when it describes the Coach's work; replace implementation labels such as
  `SYSTEM / PREFERENCES` with product language or omit them. Do not expose source-system facts.
- Auth copy remains direct: sign in, create account, verify Email, reset password, and recover
  access. The six-digit code field has an explicit six-digit label and numeric input mode. Submission
  feedback uses a concise status/error region and does not erase entered Email.
- The Shell identifies the Coach from the existing display-name/email fallback and gives desktop a
  persistent sidebar. At exact 390×844 it gives one masthead Settings entry plus the existing four
  bottom-navigation destinations; Settings is not duplicated in the bottom bar. Active navigation
  is programmatically and visually distinguishable.
- Today labels income as the current local calendar month and labels entitlement attention without
  asserting anything about today’s Course Sessions. Its zero-signal Ready state reads as a completed
  overview, not an unavailable dashboard. Each attention item is a labelled link to the owning
  Student detail.
- Student roster tools precede results. First-use, archive-filter, and search-empty states say what
  was searched/selected and provide only the relevant create, view-switch, or clear-search action.
  Detail presents Student identity and available actions before lesson summary, Coach-only context,
  and the Purchase ledger. Remaining zero/negative lessons are warnings, never automatic repair.
- Settings uses clear product headings: `教練資料`, `帳號安全`, and `帳號刪除`. It preserves
  independently recoverable profile/lifecycle panels. Password and deletion actions state their
  effect plainly; immediate deletion remains available only after a 14-day countdown has begun.
- Calendar, lesson, and Exercise placeholder wording is exactly: title plus `此功能尚未提供。`; no
  secondary promise, primary action, schedule assertion, or developer explanation accompanies it.

## 4. Interaction, state, and accessibility contract

No server state or cache semantics change in A5. Existing Coach-scoped in-memory query keys,
30-second freshness, authorized Student-detail prefetch, mutation invalidation, Auth-subject cache
clearing, Loading, Error, Empty, Ready, Refreshing, Mutating, and Conflict selections remain
authoritative.

| Interaction               | Required result                                                                                                                                                                                                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cached navigation/refresh | Previously readable supported data remains visible during refresh. Refreshing is conveyed by a small status message; a failed refresh preserves data and exposes retry at the smallest affected boundary.                                                                                                           |
| Keyboard                  | Every link, button, input, tab/view switch, and attention row is reachable in a visible logical order. Enter/Space activates native controls; visible focus never falls behind the sticky mobile navigation.                                                                                                        |
| Dialogs and forms         | Create-Student, Purchase edit, and deletion confirmations lock background scrolling while open; Escape and Cancel close them and restore focus to their invoking control. The destructive confirmation input receives initial focus. Recoverable validation, transport, and version-conflict input stays available. |
| Motion                    | Respect `prefers-reduced-motion: reduce`: suppress reveal/transition motion and smooth scrolling while preserving state feedback and focus movement.                                                                                                                                                                |
| Touch/layout              | At 390×844, controls have usable tap targets, panels and forms scroll above safe-area-aware bottom navigation, and no route has horizontal overflow. Desktop retains readable density at 1440×675.                                                                                                                  |
| Unavailable routes        | The placeholder is a clear static boundary, not a fake Empty/Error/Loading state. It has no non-functional control and can be left through normal navigation.                                                                                                                                                       |

## 5. Engineering scope and test boundary

Terra has no implementation work in A5: no data contract, semantic skeleton, migration, Module,
adapter, HTTP route, typed client, query key, or mutation changes are authorized. Sol may change
route-owned TSX, shared presentation primitives, and CSS only as required by the frozen surface,
copy, accessibility, interaction, and responsive decisions above. Sol must not move business rules
into the browser or alter existing API payloads/requests.

Required evidence:

1. Focused Web tests cover the A5-presentational branches that change, including truthful
   unavailable-route copy, reduced-motion rule, focus/modal restoration, and existing cached route
   state selection where touched.
2. Browser acceptance covers signed-out Auth/recovery and signed-in Today, Students, Student Detail,
   Settings, and each unavailable route at desktop 1440×675 and exact 390×844. It proves keyboard
   navigation, modal Escape/focus restoration, destructive confirmation focus, cached navigation,
   reduced motion, no horizontal overflow, and no console error.
3. The existing live two-Coach M3 E2E proves tenant isolation and removes only its clearly isolated
   test Student. No M4 Scheduling evidence is required or claimed.
4. CI runs root `npm run check`, root `npm run build`, `git diff --check`, `npm run db:push:dry`,
   applicable Supabase advisors, the live/browser evidence above, one cohesive commit/push, and
   confirmed remote Verify plus migration-dry-run jobs for that commit.

## 6. Exit and M4 handoff

M3.5 is complete only after this A5 Sol convergence and CI evidence are complete. The next package
is M4's Contract gate, which must separately freeze the full Scheduling model and may then define
how its schedule projection joins the preserved M3 Today signals. A5 neither pre-creates that
contract nor adds a partial Scheduling seam.
