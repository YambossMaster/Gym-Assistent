# M7.5 Stage 1 — Today notifications correction

Product Owner direction: Today’s fourth signal becomes the single notification entry point. The
separate attention panel is removed. Keep the Demo-derived four-column strip, schedule timeline,
and compact secondary card.

## Behaviour

- The fourth signal is a button labelled `待處理與課程提醒`. It shows the **unread** count. Activating
  it opens an anchored panel whose viewport fits three notification rows; additional rows scroll
  inside it. Newest source occurrence first, with deterministic ID tie-break. It closes with the
  button, Escape, outside click, and navigation. Empty state is calm, with no false unread claim.
  The feed retains at most the newest 30 visible notices; the panel header shows `(count/30)`.
  Each row keeps its message on the left, with read action/status and the Workspace-local
  occurrence date **and time** aligned to the right; the dismiss control remains in the upper-right.
  Rows vertically center their content; the optional navigation arrow occupies the message area's
  right edge rather than trailing its title, and the read action/status is visibly separated from
  the date/time. At 390px the same metadata sits on a right-aligned second line so the message stays
  readable.
- The feed contains active Students whose remaining lesson count is **at most one**, current-day
  scheduled-session conflict warnings, and successfully redeemed Student reschedule links from the
  last 30 days. Planning status remains on the Course Session row, not in notifications. Other
  capability purposes, revoked/unredeemed links, cancelled sessions, and private notes are excluded.
- A source occurrence has a stable server-generated ID. A low-balance change creates a new occurrence
  when its remaining count or most recent entitlement change changes. A conflict occurrence changes
  when its Session version or conflict set changes. A redemption is identified by its link ID and
  actual `used_at`. Resolved conditions leave the active feed; source facts are never modified by
  reading a notification. Historical reschedules age out after 30 days.
- A notification stays unread when the panel is merely expanded. Balance and conflict notices have
  a subtle navigation arrow; clicking their message opens the owned route and marks them read.
  A separate `已讀` control marks an unread notice without navigation. The subdued `×` dismisses
  only that notice from this Coach's feed; it never deletes the underlying event. Read and dismiss
  actions persist in the verified Workspace. On read failure, the row stays unread; navigation
  still works. The summary displays an unpadded unread count and no redundant read count.
- Reschedule notices are informational, with no target route or arrow. New redemptions show the
  actual original and selected times as `從…改至…`, captured atomically at redemption. For legacy
  redemptions whose original time was never retained, state that it is unavailable instead of
  manufacturing a time.
- While Today is mounted and visible, quietly refresh its existing server-owned projection once a
  minute; always check when entering Today, returning to its tab, or reconnecting. Do not poll hidden
  tabs or other routes, blank cached data, show an update banner on every tick, or present polling as
  real-time push. Retain the last projection and state an update failure if a background check fails.
- The right column becomes a compact fitness quotation with source link, attribution and one short
  credential after an em dash. Randomly select one of the 12 Product Owner-supplied sayings in
  faithful Chinese translation per page mount/refresh; there is no manual change control or visible
  translation disclaimer. Correct a mistaken attribution when the cited original establishes its
  author rather than preserving a false name.

## Authority and evidence

- `GET /v1/today` appends an allowlisted notification projection. `POST /v1/today/notifications/read`
  and `POST /v1/today/notifications/dismiss`
  accepts only a server-issued ID still present in that Coach’s current feed, with a bounded schema;
  the browser cannot supply Workspace or arbitrary route/copy. No public Capability response gains
  Coach data or a browser credential.
- Keep private receipt rows in `app_private` with Workspace RLS, revoke public/Supabase client roles,
  and grant only the dedicated API role. Batch source/read lookup; index recent reschedule lookup.
- Verify threshold selection and source ordering/deduplication, cross-Coach read isolation, no token
  or private-note leakage, idempotent reads and stale IDs, desktop/390×844 panel, keyboard/Escape,
  scrolling, reduced motion, and root checks/build plus linked-development migration checks.

The 30-day historical reschedule window and 30-notice retention are bounded Stage 1 interaction
choices; they can be revisited in the later cross-route notification audit without claiming an
all-purpose inbox or background push delivery.
