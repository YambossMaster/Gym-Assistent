## 1. Coach job, routes, and language

The Coach can record Student purchases, optionally track venue costs, understand the current
month's purchase total, venue expenses, and calculated difference, inspect prior months, and see remaining
Student and prepaid-venue lessons. Coaches who only want Student income or a place name must be
able to keep using Scheduling without entering expense information.

- `/students/finances` remains titled **本月收支** and opens on the Workspace's current local
  month. Its **各月收支紀錄** section is an entry to historical months; it does not rename the
  route or replace the current-month overview. A selected historical month has an explicit
  year/month heading and a clear return to the current-month overview.
- `/students/venues` is the separate **場地管理** page, entered from `/students` alongside
  本月收支. It owns Venue creation, fee rules, prepaid credits, archive/restore,
  and explicit historical linking. Finance rows that refer to a Venue record open this route.
- `/students/:studentId` continues to own Lesson Purchases and shows total purchase amount, lesson
  count, and derived per-lesson reference price. The purchase editor accepts either total or
  unit price plus lesson count and immediately calculates the other. Only the exact total in
  integer minor units and ISO currency is persisted as the financial amount; a non-divisible
  unit price is labelled approximate and never silently changes the total.
- Purchase currency is a browser UI preference under `/settings` → **收支設定** and defaults to
  **TWD**. The same preference supplies the currency for new Venue rent rules and prepaid purchases without another
  currency selector in Venue management. Existing records retain their saved ISO currency when edited.
- The new-purchase dialog selects **無固定場地** or one named Venue **for that purchase**.
  無固定場地 lessons can be used at any Venue; Venue-bound lessons can be used only
  at their purchased Venue. A Student may have purchases for several Venues.
  The current Student-level `defaultVenueId` is insufficient as the source of
  scheduling eligibility and must not override purchase-derived choices.
- Calendar and fixed-rhythm scheduling derive eligible Venues from that
  Student's purchases. Preselect the only eligible Venue; if several are
  eligible, use the shared custom dropdown to change among them. A general
  purchase permits any active Venue. Scheduling and completion enforce the
  same rule on the server; generated Series Sessions retain the chosen Venue.
- Calendar, Session, and fixed-rhythm editors show one **場地** field. The Coach selects an
  existing Venue or enters a new name in context; a new name creates the Venue and selects
  it without losing the scheduling draft. Entering an existing name selects that Venue.
  There is no **僅記錄地點** choice or separate 地點 input for new scheduling. A new Venue
  defaults to **不記錄場地支出** and can be managed at `/students/venues`.
  Choosing **新增場地** turns the same selector slot into a text entry with in-slot
  confirm/cancel controls; it does not add another form row or shift the surrounding layout.
- Venue names are unique within one Workspace after trimming and case-insensitive matching.
  Venue management rejects a duplicate create or rename with **該場地已存在**. An in-context
  name entry selects an active existing Venue; an archived match directs the Coach to
  restore it in Venue management. Database uniqueness protects concurrent writes.
  The monthly headline contains **本月學生購課總額**, **本月場地支出**, and **本月試算差額** when
  venue expenses are tracked. It does not contain a second `課堂實得`/contribution total.
  **收支明細** includes a **底薪** income row on each configured pay day. The difference
  is recorded Student purchases plus Venue base salary minus Venue expenses recorded by
  this feature, not whole-business profit or a bank balance. When no Venue tracks costs,
  show only purchase total and a calm invitation to set up costs; do not show an apparent zero-expense
  profit. When tracking is partial, label the expense and difference **已記錄** and explain
  that untracked Venues are excluded. Per-lesson reference prices and venue costs belong in
  detail, not in another headline purchase total. Never count a Lesson Purchase again as new
  income when its Course Session completes.

## 2. Venue and fee rules

A Venue is a Workspace-owned, stable identity with a display name, active/archived status,
version, and one or more dated fee-rule versions. Its name is not the fee rule. The default
`untracked` rule means **不記錄場地支出**: no expense is inferred, no false zero is
recorded, and the Coach is not repeatedly urged to complete setup. `free` means an
explicit known zero. A Venue can be archived to remove it from new scheduling choices
without erasing historical Sessions or finance facts.
An unused Venue can be permanently deleted directly, whether active or archived, after a simple
confirmation without typed `DELETE`. A Venue referenced by a Course Session, fixed Series, Student
fixed Venue, Student purchase, Venue credit purchase, or historical Venue payout can only be archived; an
archived Venue can be restored. Historical and financial facts remain intact. Workspace ownership
and Venue version are checked for each operation. A status change without a name change must not
be blocked by another existing Venue with the same legacy name.

In Venue management, **新增場地** accepts the name and optional expense, first prepaid
purchase, and salary settings in one save. The name-only path defaults to **不記錄場地支出**
and **無底薪**. Selecting another expense type reveals only its required fields.
Creation and name editing also accept an optional Venue location/address (at most 500
characters). Show it beneath the Venue title only when provided; this display metadata
does not replace Session/Series location snapshots or change scheduling eligibility.
Venue details use the Venue name as the title and **FORM / VENUE** as the eyebrow.
The current expense type appears in smaller, muted text beside **場地支出類型**;
**無底薪** or the enabled salary summary appears beside **底薪與否？**. Both rows are
fully clickable with a trailing chevron. Name editing opens a separate simple dialog.
The detail footer places deletion at left when allowed, with **取消** and a green
**儲存** at right. Escape closes, Enter saves, and Delete opens the deletion
confirmation when focus is outside an editable field.
From Venue detail, closing, cancelling, or saving a child editor returns to
that Venue detail; an editor opened directly from a Venue card returns to
Venue management. Commission details show the current uniform percentage or
the Venue-supplied and Coach-supplied percentages beside **抽成**. Keep the two
setting rows compact and their hover background unchanged. The prepaid purchase
action appears prominently for a Venue currently using prepaid lessons, with its
purchase history and remaining balance. Show no more than three compact purchase
rows before scrolling inside that section. Each batch shows its remaining lessons
and per-lesson price in muted parentheses; completed prepaid Sessions consume the
oldest purchased batch first (purchase date, then stable ID). Per-lesson rent also
appears in muted parentheses beside its expense type. The **過往支出類型** row opens
a separate history dialog when a dated rule record exists; keep the simple
two-setting Venue free of extra separators and reserved space. Align the prepaid
and Coach-supplied section headings with the setting labels, and give each section
a clear bottom boundary before the next setting. The Venue detail footer follows
the final setting without a second divider or reserved empty row. A purchase
batch's edit dialog also offers deletion with confirmation. Deletion preserves
completed Sessions while recalculating Venue balance and the purchase month's
expense; it requires the batch's current version and Workspace ownership.
A dual-rate Venue
shows a compact count and chips for Coach-supplied Students. **+加入自帶客** opens a
separate keyboard-operable dialog and returns to the same Venue detail after closing
or saving; removing a chip keeps the Venue detail open. All other Students are
Venue-supplied by default.
Each Venue also has an independent **底薪與否？** switch. When enabled, enter a
monthly amount, currency, and pay day (day of month). Place the two numeric
inputs for monthly amount and pay day on one row, without number spinners.
Historical linkage appears only when
there are matching unlinked legacy Sessions or fixed Series. Hide the initial untracked-rule
record from the detail view; expose later dated rule changes in the detail dialog.

| Rule                  | Required Coach input                                                              | Expense event                                                                                |
| --------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Untracked             | Venue name only                                                                   | None; not treated as free.                                                                   |
| Free                  | Explicit selection                                                                | Known zero; no monetary expense.                                                             |
| Commission, uniform   | Percentage                                                                        | Venue-bound purchase: one cost on purchase; general purchase: cost per completed Session.    |
| Commission, by source | Venue-supplied and Coach-supplied percentages; Coach-supplied Student list        | Same timing, with Venue-supplied rate by default for each Student at this Venue.             |
| Per-session rent      | Fixed amount and currency                                                         | One cost per completed Course Session.                                                       |
| Prepaid venue lessons | A purchase batch: date, lesson count, total expense or per-lesson price, currency | One expense for the entire batch on its purchase date; no new expense on Session completion. |

Commission percentages are 0–100. For a Venue-bound purchase, the commission
base is that purchase's full gross price and the calculated expense belongs to
the purchase month; completing a Session using it cannot charge the commission
again. For a **無固定場地** purchase, the selected Venue is known only when a Session
is scheduled, so a completed Session uses the allocated lesson's reference
price and that Venue's applicable rate. A completed Session with no attributable
priced purchase requires a price rather than silently producing zero cost.
For dual rates, Venue-supplied is the default. The Coach marks individual
Students as Coach-supplied **at that Venue**; the Coach does not choose a source
on every Session or Series. Source means who brought the Student, not who handled payment.

Fee rules have a local effective date and immutable historical versions. A scheduled
Session references the selected Venue and the applicable rule version; a fee change does
not silently rewrite completed Sessions or purchases. The affected set follows the
Venue association and dates automatically. The ordinary editor has no
**確認影響範圍** choice or step. If an explicit historical correction changes recorded
amounts, show a read-only consequence summary before applying that correction.
If a Venue had different historical rates, the Coach records separate effective-date
versions. No browser-side calculation is authoritative.

## 3. Purchases, completion, and monthly attribution

Lesson Purchase remains the Student entitlement grant. Its full gross amount enters the
monthly purchase total once on its purchase date regardless of historical collection mode;
purchased lessons add to entitlement. The purchase's lesson count and total derive a
reference unit price. Historical collection designations and payout rows remain stored,
but do not alter the current calculation or require the Coach to enter a payout.

Prepaid Venue lessons use separate Workspace/Venue-owned purchase batches. Each batch has
purchase date, positive integer lesson count, exact total expense in integer minor units,
ISO currency, and a derived per-lesson reference price. Entering either total or unit
price plus count calculates the other, as in Student purchasing. The prepaid editor
uses the Student purchase layout without a Venue selector: purchase date and lesson
count, total and unit reference price, then a private Coach note. Money fields keep
the active draft editable, including clearing zero before entering another value;
only a valid total is submitted. The note is stored on the Venue purchase batch and
is visible only to the Coach. The full batch amount
appears **once** in the purchase month. Completed Sessions consume one Venue lesson each,
oldest batch first, and add **no** further expense. Venue remaining lessons equal
all purchased Venue lessons minus completed Sessions assigned to that Venue's prepaid
rule; zero and negative balances remain visible and never block completion. If a later
batch covers a negative balance, it first offsets the deficit; its full payment still
belongs only to its purchase month.

Every completed Session deducts one Student lesson from an eligible purchase.
At a prepaid Venue, that completion also deducts one Venue lesson. A scheduled
or cancelled Session deducts neither. Where both Venue-bound and general
purchases can cover a Session, use a Venue-bound purchase at the selected Venue
first, then a general purchase; within either pool use oldest purchase first,
then stable ID. The existing all-Venue Student balance remains visible, but
Venue-specific balances and general lessons determine scheduling eligibility.
Reopening restores the consumed Student and prepaid Venue lessons; re-completing
deducts each exactly once.

For a general Student purchase, commission and per-session rent arise on each
completed Session at the selected Venue. For a Venue-bound purchase under a
commission rule, record its commission once at purchase and no commission when
its lessons are completed. Per-session rent still arises on completion. The
completion-based cost belongs to the Session's local teaching month, even if
the Coach marks it complete later. Cancelling before completion creates no
completion-based cost. Changes to purchases, Session/Venue association, or
historical rules invalidate affected projections and recalculate without
duplicate entries.

A Venue's base salary is independent of its expense mode. When enabled, its
monthly amount and configured pay day generate one **底薪** income row in
**收支明細** on each pay date. This income enters that month and the calculated
difference once; it is not a Student purchase. Salary settings need effective
dates so later edits do not silently rewrite paid historical months. For a
configured day absent from a shorter month, use that month's last calendar
day. No partial-month salary is inferred before the first configured pay date
or after the setting ends.

All monthly boundaries use the verified Workspace's IANA time zone and a local
start-inclusive/end-exclusive interval. The Student purchase total uses its purchase date; prepaid
Venue expense uses batch purchase date; Venue-bound purchase commission uses the
Student purchase date; per-session Venue cost uses local teaching date; salary
income uses the configured local pay date.
Never sum different currencies into one difference. Show one set of totals per currency,
with no implicit exchange rate. A month with no facts is a truthful empty month, not an
error. The historical list is newest first, identifies year and month, and opens the
same detailed income/expense rows and source links as the current month. Corrections
recompute affected historical months; no silent truncation of history is allowed.

## 4. Existing location text and optional adoption

Preserve every existing Session/Series `location` string for display and Demo-import
compatibility. Add an optional Venue reference; neither migration nor name equality
silently assigns historical strings to a Venue. A legacy text-only location remains
historical data, not `free`, not an error, and not a forced finance task. When a Coach
edits its scheduling details, the one 場地 field asks for an explicit Venue choice.
New scheduling always uses a Venue, including name-only Venues with the untracked rule.
When the Coach opts into
cost tracking, provide an explicit preview to map selected old locations/Sessions to
one Venue and apply a dated rule to completed history. Only confirmed matches are
backfilled. Fixed Series carries the selected Venue into generated Sessions while
preserving its existing visible location text and M4 reconciliation behaviour.

## 5. Venue balance signal and notification

For a prepaid Venue, show **場地剩餘堂數偏低** when derived remaining lessons are at most
one, including zero and negative. Surface the current balance on the Venue management
area and add one Workspace-scoped Today notification using the existing read/dismiss
semantics, stable source-occurrence ID, and `/students/venues` target. A top-up or
reopening that resolves the condition removes it from the active feed; a later return
to the threshold creates a new occurrence. Untracked, free, commission, and per-session
rent Venues have no lesson-balance alert. Reading/dismissing the notice never changes
Venue purchases or Sessions.

## 6. Authority, operations, and interaction states

Use an authenticated, server-owned finance projection and versioned mutations. The API
derives Workspace from verified Coach identity; clients never supply `workspaceId`.
Private Venue, purchase, cost, and payout rows remain in `app_private` with tenant-safe
repository queries and private-schema RLS/role grants. Public Training Result and
reschedule projections receive no Venue finances, fee rules, receipts, or Coach notes.
Cross-Workspace Venue/Session/purchase references return `404`; stale edits return an
authorized current version and preserve recoverable form input.

The existing API operations are inventoried below and require revision for the
corrected purchase/Venue/salary behavior. Money fields
are integer minor units plus ISO currency; date-only inputs are Workspace-local dates.
Each private mutation validates every referenced row in the same Workspace. The API
returns an accepted entity and affected projection keys/months rather than exposing
unrestricted table CRUD.

| ----------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Venue list/create                   | `GET/POST /v1/venues`                                                                                    | List includes active/archived state, optional address, current rule, prepaid balance and FIFO per-batch balance; create accepts `name` and optional `address` and defaults to untracked. |
| Venue edit/archive                  | `PATCH /v1/venues/:venueId`                                                                              | `version`, `name`, `active`, optional `address`; omitted address retains its prior value; archive is reversible and never cascades into historical Sessions.                             |

Existing Session/Series create and scheduled-edit bodies gain a selected `venueId`
validated against the Student's purchase-derived eligible Venues. They do not ask
for `customerSource`; that is determined by the Venue's Student exception list. They retain
the current visible `location` snapshot. Legacy/API import text-only records remain
valid for compatibility, while the Coach scheduling UI requires a selected Venue.
The Student Purchase request carries its own optional `venueId` (`null` means
**無固定場地**), and `amountMinor` is the full gross package price. The API owns
Venue-specific entitlement and exactly-once commission attribution. New purchase UI
does not request collection mode or a collecting Venue; the backend's legacy default
remains for storage compatibility. New purchase requests reject obsolete collection fields;
new rule requests cannot select Venue collection. Existing records keep their saved amount/date and
legacy collection designation, but every purchase is counted the same way. Historical
Venue payout rows remain stored and are excluded from projections and calculation.

An existing Student-level `defaultVenueId` may remain for compatibility but
cannot grant Venue eligibility or substitute for purchase `venueId`. The detail
projection must show purchase-derived Venue choices and balances. The initial purchase currency preference
is a browser-only UI preference and never changes currency on an existing purchase.

The finance route supports Loading, Error/retry, empty purchase-only, partial tracking,
ready, cached refreshing, mutation, and version-conflict states. Keep existing data
visible during safe refresh. Venue setup can happen inside scheduling without sending
the Coach away or forcing fee setup. Use the shared custom `FormSelect` for selections.
The desktop and exact 390×844 layouts must expose the current-month figures, historical
entry, and separate Venue management route with remaining Venue lessons and the same keyboard/touch actions
without horizontal overflow or a hidden primary action.
