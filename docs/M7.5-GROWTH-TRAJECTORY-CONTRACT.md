# M7.5 Stage 1 — Growth trajectory correction

Frozen from Product Owner review on 2026-09-20. This later correction supersedes the
completed-Session-only restriction for private Student performance in M5; M5 remains a delivered
baseline. It does not change lesson accounting, scheduling lifecycle, public access, or schema.

- Both private Session and Student dialogs show `PERFORMANCE / 成長軌跡`, then Student name —
  Exercise name. Preserve the explicit action-specific no-record explanation.
- Desktop offers only 最近 10 次 / 最近 20 次. At 600px and below offer 最近 5 次 / 最近 10 次.
  Default to the smaller range; resizing preserves the smaller/larger choice. Never paginate or
  silently reduce the plotted set. With fewer records, show every available qualifying point.
- The complete selected range drives the chart, summaries, and newest-first history. Plot in
  chronological class order, with visible wording that spacing represents class order, not elapsed
  time. Display every value/date; use smaller, staggered labels for the larger range. Retain years
  and explicit axis bounds, including a non-zero lower bound when appropriate.
- Desktop combines range and compact summaries into one row; history alone scrolls. Verify 20
  actual chart nodes and readable labels at desktop sizes, and 5/10 nodes at exact 390×844.
- Saved sets marked completed contribute to private Session history and Student directory/trend
  while the class is scheduled or completed. Reopening retains qualified records; cancellation,
  deletion, removing a qualifying set, or changing its result removes the affected contribution.
  Continue grouping by Student, Session, stable Definition ID, and snapshot metric. Repeated
  occurrences contribute one maximum per Session, with existing weight conversion/rounding.
  Missing numeric values do not create zero points. Legacy/cancelled/other-tenant data is excluded.
- Server acceptance remains authoritative. Autosave responses update the Session projection;
  invalidate affected Student directory/trend caches after accepted Training/Scheduling writes.
  Pending/offline/conflicting draft changes are identified and never plotted as saved facts.
  No polling, broad prefetch, additional persistence, or Realtime subscription is introduced.
- Preserve previous completed-class defaults, Session previous-best semantics, lesson deductions,
  explicit completion, versions/conflicts, tenant scoping, and private-note allowlists.
- Evidence: regression tests must count all selected nodes and exercise responsive ranges and
  accepted point replacement; live isolated Training save must prove scheduled-class point
  creation/correction/removal in both projections without deducting a lesson. Clean up fixtures.
  Stage 1 uses focused local/browser/live checks only; push and remote CI await authorization.
