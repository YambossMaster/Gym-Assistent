# M7.5 calendar preferences — Stage 1 Contract

Product Owner direction: 2026-09-29. This is a bounded correction to the active Settings review;
M4 and M7 remain delivered baselines.

## Coach outcome

- In Settings → 工作偏好 → 行事曆設定, set the day/week display start and end by whole hour,
  including 24:00 as an end. End must be later than start. Defaults: 06:00–22:00.
- Choose Monday or Sunday as the first day of the week. This changes week and month view
  ordering and ranges; the default is Monday. It does not change recurrence weekday identity,
  scheduled instants, or availability rules.
- Choose a default Course Session length of 30, 45, 60, 90, or 120 minutes. The default is 60.
  It pre-fills new Calendar sessions and new Student fixed-schedule series. Existing sessions
  and series keep their stored lengths.
- Display hours are a viewport preference, not a scheduling restriction. Existing Course
  Sessions and Calendar Blocks outside the selected hours extend the day/week timeline so they
  remain visible. Availability shading is clipped to the visible timeline. Agenda and month
  item lists are not time-filtered.

## Authority and interaction

The four preferences belong to the verified Coach's server-owned Workspace, with the existing
versioned Workspace settings operation and conflict recovery. The Web keeps them in the existing
Coach-scoped in-memory query cache. Neither browser-supplied Workspace identity nor a new
client-only store is introduced. A setting saves when selected; while pending, relevant selectors
are disabled. Invalid start/end pairs show a local field error, while the API and database also
reject invalid values. Transport errors keep the current choice and provide the existing Settings
error boundary.

The archived Demo already offered display hours and default length but fixed Monday as the week
start. M7's Demo-import mapping intentionally skipped calendar hours when formal authority was
absent. This Stage 1 correction adds ordinary Workspace settings; the completed M7 import mapping
is not changed here.

## Acceptance

- API validation, Workspace version conflict, database constraints/defaults, and two-Coach
  isolation remain intact.
- Week and month range tests cover Monday and Sunday. An authenticated browser check changes
  preferences, reloads or revisits Settings, and confirms Calendar and new-session behavior.
- Desktop and exact 390×844 Settings rows, open menus, and day/week Calendar remain usable with
  no horizontal overflow. A scheduled lesson beyond the selected display end remains visible.
- Stage 1 remains local for Product Owner review; Main delivery and exact-SHA remote CI require
  an explicit early checkpoint request or the Stage 2 delivery gate.
