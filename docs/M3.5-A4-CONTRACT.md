# M3.5-A4 Contract — Today signals from supported M3 data

> Frozen 2026-09-13. Product Owner explicitly decided that every capability requiring M4 remains
> M4-owned or later. This Contract therefore consumes only existing M3 Student/Lesson and Workspace
> authority; it creates no Scheduling data, model, operation, or browser inference.

## 1. Coach job and route boundary

A signed-in Coach opening `/today` needs a calm, current-workspace read of the existing signals
that can affect follow-up work: active Student count, this local calendar month's recorded manual
income, and active Students whose remaining entitlement is low or negative. It is not a lesson
agenda until M4 supplies authoritative calendar facts.

| Surface  | Frozen responsibility                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------- |
| `/today` | Display the M3-supported current-workspace signals and route each entitlement attention item to its Student detail. |

Course Session dates/times, daily session rows/counts, location, status by local day, schedule
conflicts, availability, blocks, fixed rhythm, Calendar navigation, training-plan state, and
Training data are out of scope. The route must not state or imply that no scheduled lessons exist.

## 2. Demo reference and deliberate deviation

The archived Demo supplies the dashboard's calm hierarchy, information density, and attention-first
intent. Its daily timetable, progress bar, Calendar destination, schedule-conflict count, and seeded
monthly comparison are deliberately deferred because they depend on M4 calendar authority or
non-authoritative Demo facts.

M3.5-A4 has no `no sessions` empty state. It has a valid zero-signal Ready state: zero active
Students, no income in the current local calendar month, and no attention items. That state is not
an assertion about the Coach's schedule.

## 3. Projection, time, and authorization contract

### `GET /v1/today`

The endpoint requires the existing authenticated Coach identity. The server resolves the one
Workspace and its IANA time zone; the browser sends no Workspace ID, date, time zone, or period.
The server's injected current instant determines `date` and the income boundaries in that Workspace
time zone. The response is:

```ts
{
  today: {
    date: string // YYYY-MM-DD in the Workspace time zone
    timeZone: string // Workspace IANA time zone
    summary: {
      activeStudents: number
      incomePeriod: {
        startsOn: string // first local calendar day of date's month, YYYY-MM-DD
        endsOn: string // first local calendar day of the following month, YYYY-MM-DD; exclusive
      }
      incomeByCurrency: Array<{
        currency: string // ISO-4217
        amountMinor: number // non-negative integer; summed within [startsOn, endsOn)
      }>
      attentionCount: number
    }
    attention: Array<{
      kind: 'low_lesson_balance'
      student: { id: string; name: string }
      lessonSummary: { purchased: number; completed: number; remaining: number }
      targetRoute: string // `/students/${student.id}`
    }>
  }
}
```

`incomeByCurrency` is sorted by currency ascending and omits currencies with no matching Purchase.
Its membership uses the instants corresponding to the local boundaries, start-inclusive and
end-exclusive. `activeStudents` counts only active Students at read time. `attention` includes only
active Students whose server-derived `remaining <= 2`; it is ordered by remaining ascending, then
Student name ascending, then Student ID ascending. `attentionCount` exactly equals its length.

The projection includes no fields beyond the allowlist above. In particular it never returns phone,
private note, linked status, Purchase ledger, Session, date/time, location, conflict, availability,
or Training data.

`401` denotes missing/invalid identity. The server returns no `404` because the endpoint has no
browser-selected private resource. Validation is not applicable because it accepts no input.
Operational failures use `5xx` without private implementation detail. This read may record activity
under the existing authenticated-product-operation rule; it does not mutate business data and has no
version or conflict state.

## 4. Route state and cache contract

The existing memory-only Coach-scoped TanStack Query cache gains `queryKeys.today(coachId)`. First
load with no data is Loading. A response, including zero signals, is Ready. A refetch with cached
data is Refreshing while the cached signals remain readable. A failed first load is a recoverable
route Error with retry; a failed refresh retains cached signals and uses the smallest truthful
refresh-failure indication. There is no Not Found, session Empty, mutation, or conflict state.

Student create/update/archive/delete and every Lesson Purchase create/update/delete invalidate this
Coach's Today key as well as their existing affected keys. Workspace time-zone updates invalidate
Today because `date` and income-period boundaries may change. The cache clears on Auth subject
change or sign-out. No Today response is persisted, prefetched across Coaches, or added to PWA API
caching.

## 5. Product, interaction, and copy decisions

On desktop and exact 390×844 mobile, Sol gives the three signal groups a calm dashboard hierarchy:
current local date/Workspace context, active-Student and period-scoped income summary, then
actionable entitlement attention. An attention item is a keyboard-accessible Student-detail link.
Zero values remain legible and do not become an error, Calendar prompt, or schedule assertion.

The final Traditional Chinese copy must make the income period explicit, identify entitlement
attention without diagnosing or repairing it, and never claim synchronization, Calendar facts,
unavailable course data, or Demo seed comparisons. At 390×844 all summary and attention links remain
readable and actionable above the safe-area-aware bottom navigation, without horizontal overflow.

## 6. Terra implementation and evidence boundary

Terra may add a route-shaped Today reader/Module seam, adapter queries, the authenticated HTTP
route, typed client, Coach-scoped query key, invalidation wiring, deterministic fixtures, and
semantic unstyled Loading/Error/Ready/Refreshing boundaries. Terra may not select layout, spacing,
colour, typography, responsive composition, interaction styling, animation, or end-user wording.

Required evidence:

1. Module and adapter tests prove Workspace derivation, time-zone local-month boundaries (including
   a UTC boundary crossing), multi-currency grouping, active-only count/attention, low/negative
   ordering, and no private-field leakage.
2. HTTP tests prove `401`, two-Coach isolation, the exact allowlist, and rejection-by-absence of
   browser-supplied Workspace/date/time-zone input.
3. Focused Web tests prove first-load, zero-signal Ready, cached-refresh, first-load Error/retry,
   query-key Coach scoping, and invalidation after Student/Purchase/time-zone mutations.
4. Sol browser acceptance proves desktop and exact 390×844 hierarchy, keyboard access, no horizontal
   overflow, period clarity, and the absence of scheduling claims.
5. CI runs focused tests plus root `npm run check`, `npm run build`, `git diff --check`, applicable
   live two-Coach/browser evidence, migration dry-run only if a migration is introduced, one cohesive
   commit/push, and confirmed remote Verify and migration-dry-run jobs.

## 7. Exit and M4 handoff

This Contract is frozen. Terra implements only the M3 data flow and semantic states above; Sol then
converges the product surface. M4 later freezes and implements the complete calendar-backed Today
projection, including Course Session fields and schedule conflicts, as a distinct Contract.
