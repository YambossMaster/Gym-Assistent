## Reproduction and hypothesis register

Command: `npx vitest run src/pages/training/MobileNoteEditor.test.tsx --maxWorkers=1 -t 'unmarked|delayed|browser-created'` from `apps/web`. Before the fix it fails four targeted cases in about two seconds: a later unmarked child splits the previous paragraph (`第一段\n\n第二段` instead of `第一段\n第二\n段`); an only unmarked child throws without saving a newline; a delayed focus frame moves the newly typed caret; and `<br>` inside a marked block saves `原文續寫` instead of `原文\n續寫`.

## Repeatable recurrence checklist

1. Confirm the installed PWA build/asset identity and whether the note value was saved; separate persistence from editing. Do not overwrite the affected note while collecting evidence.
2. Replay: type in an existing lower paragraph; Return mid-line and at line end; press Return twice; type before the next animation frame; repeat after composition (Chinese keyboard), after a toolbar action, and after confirming/reopening note focus.
3. Inspect the event sequence (`keydown`, `beforeinput` inputType/cancelable/isComposing, `input`, `compositionend`), selection anchor/offset before each Return, and whether the editor has marked blocks, unmarked child blocks, or nested `<br>`. Avoid logging note text.
4. Match observations to H1–H8; rerun `npx vitest run src/pages/training/MobileNoteEditor.test.tsx --maxWorkers=1` and the related Training Workspace gesture test. Add a new red case before another fix if the device trace differs from these modeled paths.
5. Recheck type/format/diff and the affected-file preflight. Follow the authorized PR, Main and deployment gates for the reviewed version, then replay the actual installed iPhone path after deployment.
